\begin{abstract}
We present a baseline neural machine translation system from Ge'ez to Amharic using a character-level bidirectional LSTM encoder--decoder with additive attention. The model is trained on approximately 17{,}416 parallel verse pairs from the AGE corpus with masked cross-entropy loss, dropout regularization, and teacher forcing. At inference we compare \emph{greedy} decoding (argmax at each step) with \emph{beam search} (width~5, length normalization, and repetition penalties). On held-out AGE data the model reaches about 49.9\% masked character accuracy and produces grammatically plausible Amharic, but corpus BLEU remains low (about 4.0) because predictions are often shorter than references and lexically mismatched. Batch translation of out-of-domain Ge'ez from the Book of Jubilees (Kufale) without parallel Amharic training data shows template repetition and domain shift. We argue that full machine translation quality is limited primarily by scarce in-domain parallel data rather than architecture alone, and outline plans to incorporate additional books.
\end{abstract}

\section{Introduction}
Ge'ez is a classical Semitic language used for Ethiopian Orthodox liturgical and historical texts; Amharic is a modern Semitic language spoken in Ethiopia. Automatic translation between them supports accessibility of scripture and philological work, but resources are limited compared to high-resource language pairs.

This project implements an end-to-end pipeline in TensorFlow/Keras: data loading, character tokenization, sequence-to-sequence modeling with attention, training on Apple Silicon (M1), and decoding with both greedy and beam search. We document what the system learns, how decoding strategies differ in practice, and why the output should be interpreted as a \emph{baseline} rather than production-ready translation.

\section{Data}
\subsection{Training corpus (AGE)}
The primary parallel corpus is \texttt{data/AGE.csv}, containing roughly 17{,}416 aligned Ge'ez--Amharic sentence pairs. We use a 90/10 train--validation split. Character-level tokenization avoids out-of-vocabulary issues for rare Ge'ez characters; source and target sequences are padded to dynamic maxima (96 characters at the 95th percentile of training lengths).

\subsection{Out-of-domain test (Kufale)}
\texttt{data/Kufale.csv} provides Ge'ez with English glosses but \textbf{no Amharic references}. We exported Ge'ez lines to \texttt{artifacts/geez\_input.txt} (1{,}270 lines) and ran batch inference to study cross-book generalization. Because the model never saw Kufale--Amharic pairs during training, poor fidelity there is expected.

\subsection{Data limitation (main bottleneck)}
State-of-the-art machine translation typically requires millions of sentence pairs. With $\sim$17k pairs from a single book domain:
\begin{itemize}
  \item The model memorizes frequent Amharic function phrases ({\ethiopic e.g.\ ``እግዚአብሔርም እንዲህ አለው''}).
  \item Character accuracy $\approx$50\% implies about half of all next-character decisions are wrong; fluent local text can still diverge globally from the reference.
  \item New books (Jubilees, law codes) introduce vocabulary and style not covered by AGE.
\end{itemize}
Additional parallel Amharic for Kufale and other texts is the most important path to improved translation quality.

\section{Methodology}
\subsection{Model architecture}
The encoder embeds Ge'ez character indices, passes them through a bidirectional LSTM (128 units per direction on the M1 profile), and initializes the decoder LSTM state. The decoder is also character-level with additive attention: decoder hidden states query encoder outputs; a context vector is concatenated and projected to vocabulary logits. Dropout is applied on embeddings (0.2), LSTM recurrent connections (0.2), and attention concatenation (0.4). Label smoothing (0.05) is used during training. The model has on the order of 725k trainable parameters.

\subsection{Training objective}
Loss is \textbf{masked sparse categorical cross-entropy}: padding index 0 is ignored so the model cannot achieve low loss by predicting padding only. We track \textbf{masked token accuracy} on non-padding target characters. Training uses Adam ($\mathrm{lr}=3\times10^{-4}$), early stopping on validation loss, and float32 precision (mixed float16 was disabled after NaN issues on Metal).

\subsection{Special tokens}
Begin- and end-of-sequence are single Unicode control characters (\texttt{\textbackslash u241e}, \texttt{\textbackslash u241f}) so char-level tokenization does not split multi-character markers like ``\texttt{<s>}''.

\subsection{Decoding strategies}
\paragraph{Greedy search.}
At each step the model selects $\arg\max$ over the vocabulary. Implementation forbids padding and BOS; a repeat penalty down-weights recently emitted characters to reduce loops. Greedy is fast ($O(T)$ forward passes per sentence) but errors are irreversible---one wrong character skews all future attention.

\paragraph{Beam search.}
We keep the top $k{=}5$ partial hypotheses ranked by cumulative log-probability with Google-style length normalization ($\alpha{=}1.0$) and a minimum output length proportional to source length (ratio ${\approx}0.35$--$0.45$ of Ge'ez characters) to avoid ultra-short generic outputs. Beam explores multiple futures and often yields more fluent, longer Amharic than greedy on the same checkpoint.

\subsection{Qualitative comparison: greedy vs.\ beam}
We observed the following patterns on the same trained checkpoint:

\begin{enumerate}
  \item \textbf{Greedy} often collapsed to short generic religious phrases ({\ethiopic ``እንዲህም አለ።''}) or character loops when repeat penalty was insufficient.
  \item \textbf{Beam} produced longer, more sentence-like Amharic with fewer abrupt stops, but still frequently mismatched the reference content.
  \item After adding minimum-length constraints and stronger length penalty, beam outputs lengthened but could still repeat {\ethiopic ``እግዚአብሔር''} on unseen Kufale lines.
\end{enumerate}

\subsection{Out-of-domain batch (Kufale)}
Translating 1{,}270 Jubilees Ge'ez lines yielded:
\begin{itemize}
  \item 0 exact string matches to any reference (no Amharic gold available).
  \item 122 lines with the same template {\ethiopic ``እግዚአብሔርም እንዲህ አላቸው።''}
  \item Mean output length 43 vs.\ source 94 characters (ratio $\approx$0.38).
\end{itemize}
This confirms \textbf{domain shift}: the model defaults to high-frequency biblical Amharic patterns learned from AGE.

\section{Discussion}
\subsection{Why this is not yet full machine translation}
\begin{enumerate}
  \item \textbf{Data volume and diversity.} $\sim$17k pairs cover one textual tradition; MT quality scales with parallel data.
  \item \textbf{Character-level modeling.} Long sequences increase difficulty; subword (SentencePiece) methods may help after more data are collected.
  \item \textbf{Evaluation mismatch.} Char-BLEU is strict; human judgment may rate some outputs as partially understandable while metrics stay low.
  \item \textbf{Out-of-domain inference.} Kufale without Amharic supervision is a zero-shot stress test, not a fair in-domain benchmark.
\end{enumerate}

\subsection{What worked}
Masked loss fixing, BOS/EOS token design, float32 training stability, regularization, and beam search with length controls turned an initially non-learning model into one that emits coherent Amharic fragments with measurable validation accuracy.

\subsection{Future work}
\begin{itemize}
  \item Add parallel Amharic for Kufale and upcoming books; retrain or fine-tune.
  \item Human evaluation (adequacy / fluency) on a fixed test set.
  \item Compare Transformer baselines; tune beam width and length penalty on dev set.
  \item Strip zero-width characters from decoder output; export merged CSV with English glosses for philological review.
\end{itemize}

\section{Conclusion}
We built a complete Ge'ez--Amharic translation pipeline with BiLSTM attention, documented training and decoding choices, and compared greedy vs.\ beam search empirically. The system demonstrates learning ($\approx$50\% character accuracy on AGE validation) but remains a \textbf{baseline} constrained by limited parallel data. Honest reporting of low BLEU, short outputs, and Kufale template collapse is essential; expanding the corpus is the primary lever for true full-sentence translation quality.
